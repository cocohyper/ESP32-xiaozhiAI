二、原固件主机测试：已执行，但未全部通过

命令：python -m unittest discover -s scripts/tests -v
运行结果：147 项，报告 errors=12、skipped=25，完整测试集未通过。
主要环境问题：
1. 五项测试会把当前目录切到 TemporaryDirectory 内，并在切回前尝试清理。
   Windows 不允许删除仍作为当前目录使用的目录，报告 WinError 32/5。
   涉及 test_build 的配置选项、目标配置和 ZIP 重建相关用例。
2. 五个 CI 工作流用例默认编码读取 UTF-8 文件时遇到 GBK 解码错误。
   设置 UTF-8 重试后，进入下一步但由于环境中没有 Bash 仍无法完成；
   其中一个用例含两个子场景，因此重试日志出现 6 条错误记录。
3. OggDemuxer 的一项主机编译测试直接调用 c++，当前环境没有该编译器。
4. 一项启动提示测试遇到 GBK 解码错误，UTF-8 重试后按测试原有逻辑因
   缺少 C++23 编译器而跳过。其他 C++ 主机用例也有类似跳过情况。

没有为了让测试数字变绿而修改这些与 DeepSeek 接入无关的原测试和业务代码。
原始测试日志及 UTF-8 重试日志位于 docs/validation/。
建议在具备 Bash、C++23、ESP-IDF 6 的 Linux 环境再次执行原项目检查。

四、交付后验收顺序

1. 按完整说明填写服务器 IP 和 DeepSeek 密钥。
2. check --skip-model 通过后，执行 test-api 验证在线流式接口。
3. download-model 完成哈希校验，完整 check 通过。
4. docker compose config --quiet 通过后构建并启动后台。
5. 从设备所在网络访问 OTA 接口，确认 WebSocket 地址正确。
6. 将设备 OTA URL 指向该后台，重启后验证实际对话与音频链路。
